# 数据口径

attempts 按 observed_at 记录作答，presented_at 是当时分配时间，result=correct、wrong、skipped。相同 item 的重做是新 attempt，不是新题。items 含多项 skills、启用时间和退休时间，availability 以当时为准；prerequisites 是知识点间先修关系。selection_reason 是分配日志而非随机化概率。练习编号与学生编号均为虚构。

## 掌握判断口径

`learning_path/mastery.py` 在描述统计之外提供按知识点的掌握判断，模型版本号写在每个输出的 `model_version` 中：

- 每次作答按 `difficulty_hint` 加权（easy 0.7、mixed 1.0、advanced 1.3）；简单题答对证据弱，但简单题答错仍是完整负信号。
- 多知识点题的权重在各知识点间均分，并在结果中记录综合题证据占比，归因不唯一时显式提示。
- 同一题目的第二次及以后作答按 50% 降权；跳过不计错误，单独计入跳过倾向。
- 自适应分配没有覆盖的题目不产生任何证据；无证据知识点标记为 `unknown`，不能解释为答错。
- 每个知识点维护 Beta 后验（含向全体证据收缩、强度封顶的先验），输出后验均值与 80% 可信区间。`mastered` 要求区间下界不低于 0.65 **且**至少有一次中等或综合难度答对——连续做对简单题不会被判掌握；`needs_practice` 要求区间上界不高于 0.60；其余有证据者为 `emerging`。
- 输出的是概率与区间，不是无法校验的总分；练习量大只代表机会多，不直接代表学得好。

## 下一份练习建议

建议先按先修关系确定目标知识点（先修未掌握时先补先修），再在策略确定的可用题池中排序：先修可衔接、未做过的新题优先、难度与当前阶段匹配、单知识点优先。每条建议附目标后验与区间、被排除候选及原因、三分类（答对/答错/跳过，和为 1）预测，以及针对哪段证据和哪项不确定性的文字说明。题池为空（退休或被排除）时显式说明并建议调整策略；新学生走全体先验，没有历史作答的新题会标注未经实测校准。

## 教学策略

策略（先修关系、排除题池、截止日期）是查询参数，校验通过才参与计算，绝不回写源数据；先修关系不允许自环或循环。截止日期使所有判断只使用当日及之前的证据，便于复盘“当时知道什么”。

## 历史预判检验

回测对每条 attempt 重建“本题分配之前”的证据状态，只允许 `observed_at < 本题 presented_at` 的记录进入先验和个人状态，并在结果中给出泄漏检查的记录数与违规数。两种模式分别报告：

- `leave_one_student_out`：每个预测点排除该学生全部记录，模拟新学生；
- `incremental_known_learners`：保留其他学生的更早记录，评估已知学生的后续表现。

两种模式同时给出本模型与全体率基线的 Brier、对数损失、命中率和校准分箱，并单列冷启动（该生此前无记录）子集。模型未优于基线时页面会明确提示，回测结论不保证未来表现。

## 发布的学习建议

`advice_publications` 保存服务端按当时数据与策略重算后的不可变快照；之后导入新数据或调整策略都不会改变已发布内容，也不提供删除或覆盖接口。

## 数据版本

`fixtures/data.json` 是可直接导入的一份完整材料，`product.json` 保存页面默认范围。导入必须提交完整对象，不把省略字段解释为删除补丁；以规范化 JSON 的 SHA-256 标识内容，同内容多次导入复用版本。原始记录只追加版本，保存的分析材料始终指向原来版本。

页面中的范围影响当前描述，不回写源数据。`null`、缺记录与实际零不能合并；数据格式问题应在导入时明确报错，而不是生成看似成功的空结果。涉及单位、时间或关系的解释以本文件为准，统计方法和业务决策没有预设结果。

## 目录

`learning_path/domain.py` 提供现行领域校验和描述，`mastery.py` 提供掌握追踪、建议与回测，`validation.py` 处理基础引用与数值校验，`service.py` 连接领域操作和材料存档，`storage.py` 负责内容寻址数据、历史记录与发布快照，`server.py` 提供本地接口。`web/app.js` 使用接口构建交互页面，不自行推导独立口径。
